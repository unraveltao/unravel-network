# 第一阶段：网络基础与协议

本阶段建立理解代理连接所需的基础。示例面向本机观察，不要求云服务器或真实代理订阅。练习中涉及外部网络时，只访问公开测试服务或自有系统。

## 课程 1：网络分层与 TCP/IP

### 原理

网络分层把通信拆成职责不同的部分。常见的 TCP/IP 模型包括网络接口层、网际层、传输层和应用层。应用数据逐层封装：HTTP 等应用数据交给 TCP 或 UDP，再由 IP 寻址，最后通过本地链路发送。接收方向则逐层解封装。OSI 七层模型是另一种分析和教学框架；它与 TCP/IP 层次是近似映射，不应认为两套模型逐项完全相同。

代理通常工作在应用层或传输层附近：应用代理理解 HTTP 等协议；转发型代理可能主要处理连接和字节流。分层有助于判断问题发生在名称解析、路由、传输连接还是应用请求。

### 实践

在 PowerShell 查看本机接口、地址和路由：

```powershell
Get-NetIPConfiguration
Get-NetRoute -AddressFamily IPv4 | Select-Object -First 10
```

记录活动网卡、默认网关和 DNS 服务器。不要公开粘贴包含个人网络标识的完整输出。

### 验证

- 能指出默认路由使用的网关。
- 能解释一次浏览器请求至少经过应用、传输和 IP 寻址等职责。
- 断开网络后，确认本机接口信息仍可读取，而远程连接状态会变化。

### 常见错误

- 把 OSI 与 TCP/IP 模型当成严格的一一对应关系。
- 看到“网络不通”就只检查网线，忽略 DNS、路由和应用层差异。
- 将 IP 地址、端口和域名视为同一类标识。

## 课程 2：IP 地址与子网

### 原理

IP 地址标识网络接口，路由器根据目标地址和路由表转发数据包。IPv4 地址由 32 位组成，通常写成四段十进制数；CIDR 前缀（如 `/24`）表示网络部分所占的位数。子网掩码和前缀决定哪些地址视为本地网络，哪些需要交给网关。

私有 IPv4 范围适合内部网络使用，不在公共互联网中直接路由。`127.0.0.1` 是本机回环地址；`0.0.0.0` 常用于服务监听所有本机 IPv4 接口，不是可供远程客户端访问的目标地址。绑定到所有接口会扩大可达范围，服务实验应优先绑定回环地址。

### 实践

```powershell
ipconfig
Test-NetConnection 127.0.0.1 -Port 80
```

若本机没有 80 端口监听，连接失败是预期结果。用 `ipconfig` 找到本机 IPv4 地址和掩码，手动判断本地网络前缀；不要把本机网络信息发布到公开文章。

### 验证

- 能解释本机回环地址与局域网地址的区别。
- 能读懂 CIDR 前缀的含义，并判断目标是否通常需要经由网关。
- 能说明为什么代理初期应仅监听 `127.0.0.1`。

### 常见错误

- 将 `0.0.0.0` 当成远端连接地址。
- 忽略掩码，只凭地址前几段猜测两个主机是否在同一子网。
- 把私有地址误认为加密或安全机制。

## 课程 3：DNS 名称解析

### 原理

DNS 将域名映射为 IP 地址，并可提供其他记录类型。客户端通常先查询配置的递归解析器；缓存可能让后续查询更快。DNS 解析成功只说明拿到了地址，不代表目标端口可达、服务正常或 TLS 证书有效。

在代理场景中，“由客户端解析域名”还是“由代理端解析域名”会影响 DNS 查询位置、隐私和故障表现。不同代理协议处理方式不同，后续应通过抓取或日志确认实际行为。

### 实践

```powershell
Resolve-DnsName example.com
nslookup example.com
```

比较两种命令返回的记录和解析器信息。将 `example.com` 替换为你有权访问的公开域名，不在公开笔记中保留内部域名。

### 验证

- 能确认域名是否解析以及返回的地址记录。
- 用 `Test-NetConnection <地址> -Port 443` 单独检查 TCP 端口连通性。
- 能解释“DNS 成功但网页仍打不开”的可能原因。

### 常见错误

- 将 DNS 解析失败与 TCP 连接失败混为一谈。
- 只清理本机缓存，却忽略递归解析器缓存或网络策略。
- 把 DNS 返回的某个地址固定写入配置，忽略地址可能变化。

## 课程 4：TCP 与 UDP

### 原理

TCP 提供有序、可靠的字节流，建立连接并通过重传等机制处理丢包；应用层仍需定义消息边界。UDP 以数据报为单位，不保证送达、顺序或去重，开销较低，应用可自行实现所需机制。两者都使用端口区分主机上的服务。

代理是否支持 TCP、UDP 或两者，取决于代理协议和实现。仅能转发 TCP 的代理无法自动承载任意 UDP 流量。

### 实践

```powershell
Get-NetTCPConnection -State Listen | Select-Object -First 10
Get-NetUDPEndpoint | Select-Object -First 10
```

观察本机监听端点，并将地址、端口和协议记入私人笔记。也可以用 `Test-NetConnection example.com -Port 443` 观察 TCP 建连结果。

### 验证

- 能说明 TCP 连接状态与 UDP 端点列表的区别。
- 能说明端口相同但传输协议不同，仍是不同端点。
- 能判断一个只支持 TCP 的实验代理不能直接证明 UDP 可用。

### 常见错误

- 把 TCP 描述为“应用消息”传输，忽略它实际提供字节流。
- 认为 UDP 一定更快或不可靠就完全不能使用。
- 只检查端口号，不检查对应传输协议和本机防火墙规则。

## 课程 5：HTTP 与 HTTPS

### 原理

HTTP 定义请求与响应，包括方法、路径、头部和消息内容。HTTPS 是通过 TLS 保护的 HTTP 通信：TLS 提供加密、完整性保护，并通过证书验证服务端身份。TLS 建立之后，中间转发者通常看不到加密的 HTTP 路径和内容，但仍可能观察到连接地址、时序和流量大小等元数据。

HTTP 正向代理可能收到绝对形式的目标 URL；HTTPS 常通过 `CONNECT` 建立到目标的隧道，再由客户端与目标完成 TLS 握手。是否解密 HTTPS 内容是另一类高风险设计，不属于本地入门练习范围。

### 实践

```powershell
curl.exe -I https://example.com
curl.exe -v --max-time 10 https://example.com
```

观察响应状态、TLS 握手信息和连接过程。不要使用浏览器或命令行选项关闭证书校验来“修复”证书错误。

### 验证

- 能区分 HTTP 状态码与 TCP 连接状态。
- 能说明 TLS 证书验证失败时客户端应拒绝信任该连接。
- 能描述 HTTPS 隧道代理与 TLS 解密代理的差异。

### 常见错误

- 将 HTTPS 等同于“代理完全看不到任何信息”。
- 遇到证书错误就关闭校验，掩盖中间人或配置问题。
- 把 `CONNECT` 隧道误认为代理已经读取 HTTPS 请求正文。

## 课程 6：代理工作原理

### 原理

代理是位于客户端和目标服务之间的中间服务。正向代理通常代表客户端访问外部目标；反向代理通常位于服务端前方，将请求转给后端服务。代理可以处理认证、路由、日志或连接管理，但具体能力取决于协议和实现。

一次代理请求通常经过：客户端选择代理、连接代理监听端点、代理解析或转发目标、目标返回数据、代理将响应交还客户端。代理改变了连接路径和信任边界，不能自动提供端到端加密，也不能保证匿名或安全。

### 实践

先使用本地临时 HTTP 服务观察“客户端—服务端”直连，再阅读代理软件的本地配置和监听状态；本阶段不需要搭建公开代理。若已有安全、可信的本地代理，可在命令中显式设置代理并访问公开测试域名：

```powershell
curl.exe --proxy http://127.0.0.1:<本地代理端口> -I https://example.com
```

仅当该端口确实是你启动且了解的本地服务时才执行。不要把本地代理端口暴露到公网。

### 验证

- 对照直连与代理连接，确认客户端配置是否实际生效。
- 检查代理监听地址，确认只绑定回环接口。
- 能画出客户端、代理和目标服务之间的请求与响应路径。

### 常见错误

- 把代理、VPN、NAT 和防火墙视为相同机制。
- 代理配置错误时仍将请求误认为经过代理。
- 以为代理自动加密客户端到代理的连接或隐藏所有流量信息。
- 将实验代理监听在所有网卡上，导致局域网或公网可访问。
